# GDScript 单步跳过不可执行行设计

## 目标

Godot 3.6.3 的 GDScript 单步调试只在真正可执行的源码语句处停下。空白行和纯注释行不消耗一次 `next`，同时保持断点、调用栈行号、分支、循环和函数调用的既有语义。

## 根因

当前解析器会为物理换行创建 `TYPE_NEWLINE` 节点，编译器随后把每个节点都转换成 `OPCODE_LINE`。虚拟机把 `OPCODE_LINE` 当成单步计数点，因此空白行和纯注释行也会让 `lines_left` 归零并触发暂停。

## 方案

在 GDScript 编译阶段根据可执行 AST 语句生成行号指令，而不是根据换行节点生成。`TYPE_NEWLINE` 只承担解析期的源码结构作用，不再直接产生字节码。每个实际语句编译前，通过语句节点的 `line` 写入 `OPCODE_LINE`；同一源码行的连续语句不重复写入停点。

控制流需要保留精确行号：`if`、`for`、`while`、`match`、`return` 和局部变量声明以自身 AST 行号作为停点；进入子块后，第一条实际语句必须产生停点；`else` 不单独制造一个没有执行体语句的停点。显式 `breakpoint` 语句仍由 `OPCODE_BREAKPOINT` 控制。

不采用运行时读取源码过滤，因为它会增加每次单步的文件解析开销，并可能误判多行字符串；也不采用 VS Code 自动连续发送 `next`，因为额外协议往返会引入闪烁、竞态和延迟。

## 验证

新增最小 GDScript 夹具，覆盖连续空白行、连续纯注释行、行尾注释、同一行多语句、分支和循环。真实 v2 调试客户端记录每次 `next` 后的停止行，断言序列只包含可执行语句行。随后运行 GDScript 编译相关测试、debugger v2 集成门禁和 Brotato 压力回归，并重新构建交付用 Godot 可执行文件。
